# CI/CD for lab-automation-demo

## Context

CI already exists ([.github/workflows/ci.yml](../../.github/workflows/ci.yml)). It is one job that runs `uv sync --locked`, `pre-commit run --all-files` and `pytest` on every push and PR. Three things are missing:

- Nothing tests the system the way the README tells people to run it: a real `uvicorn` process with `demo.py` and the `ai_draft` replays as clients. `tests/test_dashboard.py` runs `demo.py` only against an in-process app.
- There is no release path. The project is at version 0.1.0 and has no tags.
- The current job has no caching, no explicit token permissions, no timeout and no dependency updates.

The author chose **tagged releases only** for CD: pushing a `v*` tag builds the wheel and sdist, smoke-tests the built wheel, and attaches both to a GitHub Release. There is no container and no hosted deploy, so D7's "no containers" cut still stands. CI runs on **Ubuntu only**.

Following the repo's spec-driven practice, this plan is committed to `docs/plans/` before any code, and the spec, decisions and README are updated to describe what CI/CD actually does.

### 1. `scripts/smoke.py`: an end-to-end smoke check (new, about 60 lines)
It is written in Python, so it runs on the Windows dev machine as well as in CI. It does this:
1. Creates a temporary directory and sets `LABDEMO_DB` to a fresh file inside it. A fresh database avoids the overfill that appears after about six runs.
2. Starts the API with `subprocess.Popen`. By default the command is `uv run uvicorn labdemo.api:create_app --factory --port <port>`. A `--server-cmd` argument overrides it, which the release job uses to run the installed wheel.
3. Polls `GET /docs` with `httpx` for up to 30 s, and fails with the server's output if it never comes up.
4. Runs these clients with `LABDEMO_API_URL` pointing at that port, from the repo root (`ai_draft` resolves `recordings/` relative to the working directory, see `src/labdemo/ai_draft.py:34`):
   - `python demo.py` must exit 0. It already returns 1 on any unexpected status or body (`demo.py:54-110`).
   - `python -m labdemo.ai_draft --replay overdose-250ul` must exit **1**: validation fails and approval is not offered (`ai_draft.py:131`).
   - `python -m labdemo.ai_draft --replay column-1-50ul` with stdin `y\n` must exit **0**: approved, submitted and accepted (`ai_draft.py:148`).
5. Terminates the server in a `finally` block and prints one PASS/FAIL line per step. It exits non-zero if any step failed.

The script reuses `demo.py` and `ai_draft.main` as they are. The production code does not change.

### 2. Harden [.github/workflows/ci.yml](../../.github/workflows/ci.yml)
- **Triggers:** `push` on branches `["**"]` (every branch, as the README says, but tags go to the release workflow), `pull_request`, `workflow_dispatch`, and `workflow_call` so the release workflow can reuse the checks.
- **`permissions: contents: read`** at the top level.
- **`concurrency`:** group `ci-${{ github.ref }}`, with `cancel-in-progress: true`. The release workflow defines no concurrency group of its own, so calling CI from it cannot deadlock.
- **Job `check`** (the existing steps): `timeout-minutes: 15`, `astral-sh/setup-uv@v6` with `enable-cache: true`, and an `actions/cache@v4` step for `~/.cache/pre-commit` keyed on `hashFiles('.pre-commit-config.yaml')`. The steps themselves stay the same.
- **New job `e2e`**, which runs in parallel with `check`: `timeout-minutes: 10`, then `uv sync --locked`, then `uv run python scripts/smoke.py`.

### 3. New `.github/workflows/release.yml`
- Trigger: `push` with `tags: ["v*"]`. Top-level `permissions: contents: read`.
- Job `ci`: `uses: ./.github/workflows/ci.yml`. A release is never published unless the full gate passes.
- Job `release`: `needs: ci`, `permissions: contents: write`, `timeout-minutes: 15`. Steps:
  1. `actions/checkout@v4` with `fetch-depth: 0`.
  2. **The tag matches the project version:** `test "v$(uv version --short)" = "$GITHUB_REF_NAME"`.
  3. **The tagged commit is on main:** `git merge-base --is-ancestor "$GITHUB_SHA" origin/main`.
  4. `uv build`, which writes the wheel and the sdist to `dist/`.
  5. **Smoke-test the built wheel, not the source tree:** `uv run python scripts/smoke.py --server-cmd "uv run --isolated --no-project --with dist/labdemo-*.whl uvicorn labdemo.api:create_app --factory --port {port}"`. This proves the published artifact installs and serves the API.
  6. `gh release create "$GITHUB_REF_NAME" dist/* --generate-notes --verify-tag`, with `GH_TOKEN: ${{ github.token }}`.
- The release notes say the wheel contains the `labdemo` package (the API and `ai_draft`). The full demo (`dashboard.py`, `demo.py`, `recordings/`) runs from the source archive that GitHub attaches to every release.

### 4. New `.github/dependabot.yml`
Two update ecosystems: `github-actions` and `uv` (for `uv.lock`). Both run weekly and group minor and patch updates into one PR each. CI gates every Dependabot PR like any other.

## Verification
1. **Locally (Windows):** `uv run python scripts/smoke.py` prints PASS for all three steps and exits 0. Then break one expectation on purpose, for example expect exit 0 for the overdose replay, confirm the script exits non-zero, and revert.
2. **The wheel path, locally:** `uv build`, then `uv run python scripts/smoke.py --server-cmd "uv run --isolated --no-project --with dist/<wheel> uvicorn labdemo.api:create_app --factory --port {port}"` passes. Delete `dist/` afterwards (add `dist/` to `.gitignore`).
3. **Gates:** `uv run pre-commit run --all-files` (which also runs check-yaml on the workflows) and `uv run pytest` both pass.
4. **CI on GitHub:** push the branch. The `check` and `e2e` jobs both go green. A second quick push cancels the superseded run.
5. **Release (outward-facing, done by the repo owner):** after merging to main, tag `v0.1.0` and push the tag. The Release workflow re-runs CI, passes the version and main-ancestry checks, smoke-tests the wheel and publishes a GitHub Release with the `.whl` and `.tar.gz` attached. A negative check: a tag whose version does not match `pyproject.toml` fails at step 2 and publishes nothing.
